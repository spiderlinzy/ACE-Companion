# 合规自查清单（公开版）

> 本清单把全书控制要点压缩为可勾选的自查项，供 AI 团队做第一轮体检。它不是法律意见，也不替代针对具体系统的符合性评定；建议先跑“三大缺口体检”，再按治理底座逐项展开。勾选状态只代表自查结论，正式合规仍需结合适用法域与法律顾问意见。

## 一、三大缺口体检（先回答这三组问题）

**保护缺口（系统上线前 · 输入端）**

- [ ] 已完成系统风险分级，能说明它是否落入高风险类别及判定理由
- [ ] 已排查禁止性实践（如操纵、利用脆弱性、不当评分等），并保留排除记录
- [ ] 训练 / 检索数据有出处与授权记录，做过代表性与偏差审查
- [ ] 特殊类别（敏感个人）数据的使用具备合法性基础与最小化措施

**监督缺口（运行中）**

- [ ] 关键行为有日志，明确记录范围、留存期限与访问权限
- [ ] 系统输出质量、漂移与安全指标有持续监控和告警阈值
- [ ] 高风险动作有人工监督与一键中止 / 接管能力
- [ ] 有明确的风险重评估触发条件：重大功能变更、场景转移、重大安全事件、监管变化、新型风险

**救济缺口（出错后）**

- [ ] 有事故分级、上报时限、根因分析与整改闭环流程
- [ ] 面向用户 / 受影响人的告知与解释话术已准备
- [ ] 投诉入口、人工复核与纠正渠道可用且有人负责

## 二、治理与文档底座

- [ ] 有 AI 系统清单（见[证据模板](evidence-templates.md)），覆盖自研、外购模型与嵌入式组件
- [ ] 有风险登记册并按“缓解前—缓解后—残余风险”持续更新
- [ ] 技术文档按附件 IV 要素维护，版本与系统版本对应
- [ ] 明确提供者 / 部署者身份；部署者触发“变为提供者”的三种情形已在合同与设计中排查
- [ ] 供应商与模型来源可追溯，合同中约定信息提供、日志配合与事故通知义务
- [ ] 团队完成与角色匹配的 AI 素养与安全培训，保留培训记录

## 三、生成式 AI 专项控制

**提示注入与越权**

- [ ] 系统指令与外部内容在架构上隔离，外部内容默认不可改写高信任规则（PTB）
- [ ] 工具 / 插件调用采用白名单、最小权限与危险动作强制人工确认
- [ ] 对间接注入（检索文档、网页、工具返回）有过滤与指令层级约束

**数据与隐私**

- [ ] 检索语料与上下文做敏感信息识别与脱敏，避免把机密 / 个人数据送入外部模型
- [ ] 明确数据留存、删除与模型不用于训练的条款配置

**幻觉与输出可靠**

- [ ] 事实性回答优先 grounding 到可信来源，输出置信度受来源等级约束（FTH）
- [ ] 高风险结论附引用与不确定性提示，无来源时明确拒答或转人工
- [ ] 输出层有不安全内容与越权格式校验，而非只依赖输入过滤

**验证与上线**

- [ ] 上线前完成基准测试与红队测试，留存测试集、攻击用例与结果
- [ ] 设定说明性而非“通用标准”的验收阈值，并按自身误报 / 漏报代价校准
- [ ] 建立上线后评测集回归机制，模型升级后重跑核心安全用例

## 四、按优先级落地的顺序建议

1. **P0（先保命）**：资产清单、风险登记、日志留痕、人工接管、数据脱敏、提示注入分层防御。
2. **P1（可审计）**：技术文档、供应商合同条款、输出校验与引用接地、监控告警、事故响应预案。
3. **P2（成体系）**：成熟度模型、合规治理平台、自动化证据采集、红队常态化、培训与演练。
